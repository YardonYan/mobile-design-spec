# H5 页面规范

万能适配的生存指南。H5 是最自由也最容易失控的平台, 核心原则: 弹性适配, 留有余量。

## 设计基准宽度

- 375px: 移动端设计稿, @2x 出图用 750px
- 750px: 最大内容宽度, 超出居中或留白

375px 与 iOS 的 390 / 402pt 逻辑宽度接近, 也和小程序 750rpx 天然对齐, 仍是移动端最通用的画布。

## 视口单位

| 单位 | 含义 | 支持情况 |
| --- | --- | --- |
| vh / vw / vmin / vmax | `vh` 等于 `lvh`, 按最大视口算 | 全平台 |
| svh / lvh / dvh | 小 / 大 / 动态视口高度 | Safari 15.4 (2022-03-14)、Chrome 与 Edge 108 (2022-11 起)、Firefox 101 (2022-05-31) |
| svi / lvi / dvi | 同上, 对应 vw 轴 | 同上 |

整屏容器用 `100dvh` (接受滚动时地址栏收放带来的重排), 需要绝对不被地址栏遮挡的用 `100svh`。`100vh` 在 iOS Safari 上等于 `lvh`, 地址栏展开时底部内容会被遮住, 这是老坑但仍然存在。

## 响应式断点

| 断点 | 宽度范围 | 目标设备 |
| --- | --- | --- |
| xs | < 576px | 小屏手机 |
| sm | 576 ~ 767px | 大屏手机 |
| md | 768 ~ 991px | 平板竖屏 |
| lg | 992 ~ 1199px | 平板横屏 / 小屏电脑 |
| xl | ≥ 1200px | 桌面端 |

主流框架的实际口径不完全一致, 参照值:

| 框架 | 断点 | 基准字号 |
| --- | --- | --- |
| Tailwind 4 | sm 640 / md 768 / lg 1024 / xl 1280 / 2xl 1536 | 根 16px; text-xs 12、sm 14、base 16、lg 18 |
| Vant 4 | 无断点体系, 移动优先用 px | 10 / 12 / 14 / 16px; 按钮默认高 44px, tabbar 50px |
| antd-mobile 5 | 无断点体系 | 主字号 13px (1 ~ 10 档 9 → 18px) |
| WeUI | 无断点体系 | 组件 10 ~ 17px, 按钮 17px, 行高 1.41 / 1.6 |

上表数值取自各框架发布产物 CSS, 属官方发布物而非文档正文。

## 字体与行距

| 层级 | 字号 | 字重 | 行高 |
| --- | --- | --- | --- |
| H1 | 24 ~ 28px | 700 | 1.3 |
| H2 | 20 ~ 24px | 600 | 1.4 |
| H3 | 18 ~ 20px | 600 | 1.5 |
| 正文 | 14 ~ 16px | 400 | 1.6 ~ 1.8 |
| 辅助说明 | 12 ~ 13px | 400 | 颜色 #999 |

字体栈:

```css
font-family: system-ui, -apple-system, "PingFang SC", "Helvetica Neue", sans-serif;
```

WeUI 实测用的是 `system-ui, -apple-system, "Helvetica Neue", sans-serif` (不含 PingFang SC), 因为 `system-ui` 在中文环境已能命中系统中文字体。加上 PingFang SC 更保险, 但会让非苹果设备也走一遍无效声明。MiSans、HarmonyOS Sans 的 Web 引入条款本轮未查到官方出处, 用前自行确认授权。

`clamp()` 已是 Baseline Widely available, 流式字号可直接用:

```css
h1 { font-size: clamp(22px, 5.6vw, 28px); line-height: 1.3; }
```

rem 根字号: 官方无推荐值, 主流框架保持 16px 静态根字号加组件级 px。`html { font-size: vw }` 这类动态根字号是社区方案, 会带来小数取整误差, 不是最佳实践。

## 间距

| 用途 | 数值 |
| --- | --- |
| 页面左右 padding | 15 ~ 20px |
| 卡片间距 | 12 ~ 16px |
| 段落间距 | 16 ~ 24px |
| 区块间距 | 32 ~ 48px |

## 触控目标

两套标准并存且不冲突:

- WCAG 2.2 SC 2.5.8 Target Size (Minimum), Level AA: 可点区域至少 24 x 24 CSS px, 有 spacing / equivalent / inline / UA control / essential 五类例外。这是可判定合规的底线。
- Apple HIG: 44 x 44 pt。这是体验建议, 移动端主操作按它做。
- WCAG 2.2 SC 2.5.7 Dragging Movements 不管尺寸: 拖拽操作要能用单指针替代动作完成。

所以列表主按钮按 44px, 密集的次要图标至少 24px 且彼此间距留够 (spacing 例外要求 24px 间距内无其他目标)。

## 安全区与 viewport

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

`viewport-fit=cover` 是使用 `env(safe-area-inset-*)` 的前提, MDN 仍作为标准写法推荐, 说明其作用是避开刘海等显示挖孔。取值 `auto` / `contain` / `cover`。iOS 26 的 Safari 未改变 viewport-fit、safe-area env() 或 dvh 的行为。

## 实战要点

- 整屏高度用 `100dvh` 而不是 `100vh`
- 按钮高度 44px 起步, 次要图标不低于 24px
- 行高正文至少 1.6 倍, 段落间距至少 1em
- 图片 `width:100%; height:auto` 或按比例裁切, 配合 `srcset` 出 @2x @3x
- 小于 12px 的字号: 社区常说 iOS 强制最小 12px, 未找到官方出处, MDN 只提到 `text-size-adjust` 且非 Baseline。按可读性下限处理, 不要依赖浏览器帮你放大
